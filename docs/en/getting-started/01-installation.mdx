# Installation

## Prerequisites

- [Bun](https://bun.sh) v1.1+ (package manager and runtime)
- [PostgreSQL](https://www.postgresql.org/) 15+ with a running instance
- [Git](https://git-scm.com/)

Missing PostgreSQL or Redis? If you're setting up with an agent, it handles this: `bun run init` detects what's unreachable and prints an environment-diagnostics block with the exact fix for your OS (usually `docker compose up -d`, or installing Docker first). The agent relays the options in chat and asks before installing anything.

The agent creates the folder itself (degit makes it), asks for your choices in chat — modules, site name, admin account, demo content — then runs the install and hands you the URL and generated credentials. When it finishes, open your next agent session **inside `my-app`**. Already have the files? Open your agent in the folder and type `/setup`.

**No terminal at all?** The Claude Code desktop app works the same way: new session → choose an empty folder → "Set up a new project here from https://github.com/indigo-fw/starter — ask me what you need".

## Set up by hand

No agent required — the classic path, fully supported and identical underneath.

Download the starter template (files only — no git history) and install dependencies:

```bash
bunx degit indigo-fw/starter my-project
cd my-project
bun install
```

> Use `degit` rather than `git clone` so your project starts with a clean slate — no link back to the starter's remote or commit history. `bun run init` (below) creates a fresh git repository for you.

Copy the example environment file and configure your database:

```bash
cp .env.example .env
```

Edit `.env` and set your `DATABASE_URL`:

```env
DATABASE_URL=postgresql://user:password@localhost:5432/myproject
BETTER_AUTH_SECRET=your-secret-here
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_SITE_NAME=My Project
```

## Initialize

Run the init script. It creates the database, runs migrations, creates a superadmin account, seeds default content, and **initializes a fresh git repository** for your project (then offers to set your own `origin`):

```bash
bun run init
```

This will prompt you for a superadmin email and password. For non-interactive setup (agents, CI, Docker), every question has a flag or env-var answer — e.g. `bun run init -- -y --modules recommended --admin-email you@example.com`. In `-y` mode init leaves git alone.

## Start Development

```bash
bun run dev
```

Your app is now running at [http://localhost:3000](http://localhost:3000). The admin dashboard is at [http://localhost:3000/dashboard](http://localhost:3000/dashboard).
