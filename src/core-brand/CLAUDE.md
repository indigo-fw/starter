# core-brand — CLAUDE.md

Single source of truth → all brand assets + components + `/brand` page.

`src/core-brand/` is a git subtree from `indigo-fw/core-brand`. Do not modify per-project.

```bash
git subtree pull --prefix=src/core-brand git@github.com:indigo-fw/core-brand.git main --squash
git subtree push --prefix=src/core-brand git@github.com:indigo-fw/core-brand.git main
```

## Generation workflow

Project authors edit ONE config file (`src/config/brand.ts`) and run ONE command (`bun run indigo brand:generate`) to produce favicons, apple touch icon, OG/social images, web manifest, and press-kit zip in `public/` (authoritative output list: `cli/generate.ts`). Plus a `<BrandLogo>` React component the navbar/footer/emails consume, and an MDX-rendered `/brand` page for partners/journalists.

```bash
bun run indigo brand:generate          # regenerate all assets from brand.ts
bun run indigo brand:generate --check  # validate config + report what would change (no writes)
```

Idempotent. Safe to re-run after editing `brand.ts`.

## Input modes

Three modes — discriminated union in `types/brand-config.ts`, runtime-validated by `lib/validate-config.ts` (file existence, square check, per-mode rules; the CLI errors helpfully if assets are missing). Non-obvious required fields: `text-only` **requires `faviconGlyph`**; `lockup` **requires `icon` OR `faviconGlyph`** in addition to the lockup SVG.

**Never auto-crop a lockup into a favicon** — produces bad results; force the user to provide a square source.

## DI registration (the key architectural decision)

Per the core boundary rules (`src/core/CLAUDE.md`), modules may only import from a small allowlist of project paths. `@/config/brand` is not on it, so the module does NOT import the project's brand config directly. Instead the project calls `setBrandConfig(brand)` once at boot — the same pattern as `setCommentsDeps()`, `setPaymentsDeps()`, etc.

Wiring:

- `src/config/deps/brand-deps.ts` (project-side) calls `setBrandConfig(brand)`
- The module's `module.config.ts` declares `serverInit: ['@/config/deps/brand-deps']` so `initModuleDeps()` (generated by `indigo:sync`) side-effect-imports it
- `src/instrumentation.ts` ALSO side-effect-imports `@/config/deps/brand-deps` — required because RSC runs in the Next.js bundle (separate module instance from `server.ts`), see the workspace CLAUDE.md note on module-instance separation

The call is idempotent — registering the same config twice is safe.

SVG caching: at `setBrandConfig()` time we eagerly read the referenced SVG files into memory. `<BrandLogo />` renders never touch the filesystem (server component, sync). Trade-off: SVG file changes require a server restart (acceptable for a config-grade file).

## OG image template substitution

For the `custom-svg` OG template, the CLI substitutes `{{name}}` (→ `brand.name`) and `{{tagline}}` (→ `brand.ogImage?.tagline ?? ''`) before rasterization. Whitespace inside braces is tolerated; unknown tokens pass through unchanged; values are XML-escaped.

Brand colors are **intentionally not substituted** — the OG image is treated as a designed artifact, not a derived one. Edit `og-image.svg` directly to change colors. (OKLCH→hex conversion would be needed for full color substitution and @resvg/resvg-js doesn't fully support OKLCH yet; not worth the complexity for v1.)

## Component

```tsx
import { BrandLogo } from '@/core-brand/components/BrandLogo';

<BrandLogo variant="auto" className="h-8 w-auto" />
```

Variants: JSDoc on `components/BrandLogo.tsx`. Non-obvious: `auto` renders lockup on `sm+`, mark on mobile (default in navbar); every (mode × variant) combination renders with sensible fallbacks (e.g. text-only mode renders the `faviconGlyph` square when `variant="mark"` is asked for).

## Runtime dependencies

`sharp`, `@resvg/resvg-js`, `to-ico`, `archiver`, `satori` — must be added to `package.json` when installing the module.

## Out of scope

No in-browser image editor, no AI-generated logos, no auto-cropping of non-square sources, no multi-tenant/multi-brand support (deferred until `core-multisite` integration).

## Removal

`indigo remove core-brand` removes the subtree plus `src/config/brand.ts` and `src/brand/icon.svg` (per `projectFiles`). Generated assets in `public/` stay — they're build artifacts, not module property. The navbar's `<BrandLogo>` import will go red after removal; fix `src/app/(public)/layout.tsx` with an inline SVG or another brand provider.
